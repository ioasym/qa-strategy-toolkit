# Defect Triage Process

## Required defect information

- concise title
- affected version/environment
- reproducible steps or evidence
- expected vs actual behaviour
- customer/business impact
- logs/screenshots/traces where appropriate
- frequency
- workaround
- suspected area (if known)

## Triage questions

1. Is the issue reproducible?
2. What user/business capability is affected?
3. What is the worst credible impact?
4. How often can it occur?
5. Is data/security/financial integrity involved?
6. Is there a safe workaround?
7. Does it block release or can risk be accepted?

## Output

Each triaged defect should have:

- agreed severity
- delivery priority/target
- owner
- release decision impact
- required verification scope
